# 電波人間のRPG2 マップエディタ (panana)

電波人間のRPG2 (v1.1.0, TID 00040000000A7900) のダンジョンのマップを、ブラウザ上で 2D / 3D を見ながら編集し、
LayeredFS 用の MOD (`00040000000A7900/romfs/A90C8038`) として書き出す静的サイトです。
設計: `../elpulse/docs/map-editor-design.md`、データ構造: `../elpulse/docs/map.md`。

ROM 由来のデータはリポジトリにもアプリにも含めません。利用者のダンプから、ブラウザの中だけで読み取ります
(読み取ったファイルと変換済みのモデルは、その端末の IndexedDB にキャッシュします)。

## 使い方

```bash
bun install
bun run dev        # http://localhost:5173/
bun run build      # dist/ (静的ファイル。サーバー不要)
```

入力 (どれか 1 つ):
1. 復号済みの CIA (`.cia`)
2. 復号済みの NCCH (`.cxi` / `.app`)
3. 展開済みのフォルダ (RomFS のルートのファイル `A90C8038` などと `code.bin`)

暗号化されたダンプは読めません (GodMode9 などで復号してください)。

### 操作

| 操作 | 内容 |
|---|---|
| V 選択・移動 | タイルを選ぶ (Shift で追加)。点 (出入口・宝箱など) をドラッグで移動 |
| B タイルを置く | パレットで選んだタイル (種類・文字・向き) を置く。ドラッグで連続 |
| E タイルを消す | |
| M 範囲選択 | Ctrl+C / Ctrl+V (マウスのあるセルが左上) / Del / Shift+矢印で中身ごと移動 |
| G 部屋のセル | 区画 6 のセルを付け外し |
| R / Shift+R | 向きを回す (選択中のタイル、またはブラシ) |
| [ / ] | 文字 (バリエーション) を切り替える |
| Ctrl+Z / Ctrl+Y | 元に戻す / やり直し (マップごと) |
| Ctrl+D | 選択中の点を複製 |

- 3D: 右ドラッグで回転、中ドラッグで移動、ホイールで拡大。左クリックは 2D と同じ編集操作 (地面 y=0 上のセル)。
- 天井 (マテリアル名 *ceil*) は既定で隠します。「高さで切る」で壁の上部も切れます。
- 編集内容は自動で IndexedDB に保存され、次に開いたときに読み込むかを聞きます。
- 「書き出し…」: 変更の一覧と検証結果を出し、zip または MOD フォルダへの直接書き込み (File System Access API) を選べます。
  書き出すのは変更したファイルだけです: マップ → `A90C8038`、宝箱の「中身の表の行」やモデルの上書き → ダンジョンのイベントのアーカイブ (`79B881BB` など)、宝箱の中身 → `56562135` (マスター)。
- マップ名は「山のどうくつ 地下2階」のように表示します (コード `D01B02001` も併記)。出入口の行き先マップ・地点も名前で選べます。
- 3D ではタイルに加えて、階段・扉・門・宝箱・置物・ワープホール・NPC などをゲームのモデルで表示します (「オブジェクトのモデル」で切り替え)。

### 宝箱・ギミックの追加

左ペインの「追加」で、置くものを選んでマップをクリックします (Esc で終わる)。
- 宝箱: ダンジョンのイベントの表 (EventObject) に新しい行、treasureGroup に新しい中身の行を作ります。中身は最初、同じダンジョンの宝箱の写しです。
- ダメージ床・凍った床 (区画 1)、置物 (区画 2、mapObject の行を選ぶ)。
- ギミック: ゲーム中の同じ種類のもの (スイッチ・回復の泉・穴・ワープホール・扉など) をひな形に、レコードとイベントの行を写します。動き (つながる扉や行き先など) は写し元の設定のままなので、右ペインのイベントの行の生データや行き先で直してください。
- 複製 (Ctrl+D) も、イベントの行 (宝箱なら中身の行も) を新しく作るので、元と状態を共有しません。
- 状態 (開けた・押した) はセーブ変数 0x8E の「ダンジョンの基準 (mapGroup +0x1A) + 枠 (EventObject +0x44)」に入ります。行と枠はダンジョンごとに mapGroup +0x1C 個まで (多くのダンジョンで 10 前後の空き) で、超える追加はできません。

### 宝箱の中身

宝箱 (区画 4) を選ぶと、右ペインに中身 (アイテム・重み・確率) を一覧で出します。区画 4 の +0 = ダンジョンの EventObject の行、その +0x08 = 中身の表 (treasureGroup) の行、その行に最大 10 個のアイテム {アイテム, 重み}。
開けると、並んだアイテムから重みに比例して 1 つ選ばれます。
- 「変更…」: 中身の表の全行を中身つきで一覧するダイアログで、別の行を選ぶか、今の中身を写した新しい行を作ります。行を共有している宝箱の数も出ます。
- アイテムはクリックで差し替え、「＋ 追加」で一覧表 (名前・分類で絞り込み) から選んで足し、「×」で外します。
- 中身はマスター (`56562135`) にあります。アイテム MOD (`elpulse/mod`) も `56562135` を置き換えるので、両方使うときはヘッダーの「マスター」ボタンで MOD の `mod/out/romfs/56562135` を読み込んでください。それを土台に書き出し、MOD のアイテム名も表示します。

## 構成

```
src/
  rom/      cia.ts ncch.ts exefs.ts romfs.ts blz.ts dump.ts cache.ts   ダンプ → code.bin / RomFS のファイル
  archive/  gsarc.ts lz10.ts zip.ts gstable.ts                          独自アーカイブ・LZ10・GS テーブル
  game/     codebin.ts mapdb.ts sections.ts master.ts game.ts          マップ表・マップ DB・区画・mapParts など
            events.ts objects.ts names.ts                              EventObject、オブジェクトのモデル、名前
  cgfx/     cgfx.ts texture.ts tileset.ts worker.ts loader.ts three.ts  CGFX → three.js (Web Worker で変換)
  editor/   state.ts controller.ts view2d.ts view3d.ts palette.ts inspector.ts validate.ts ...
  export/   pack.ts                                                    マップ DB → A90C8038、イベント、マスター → zip
test/
  unit.test.ts   ROM なしで動くテスト
  rom.test.ts    Python の参照実装との照合とラウンドトリップ (ダンプが必要)
  golden/export_golden.py
```

分かったこと (設計書からの補足):
- mapResource の行 = `[0] モデルのアーカイブ, [1] テクスチャのアーカイブ (469B3DC6), [2] その中のテクスチャ (bcres), [3] 空のモデル`。
  タイルのモデルはテクスチャを持たず、[2] の共有テクスチャを名前で参照する。
- CGFX の頂点バッファは 0x40000002 (インターリーブ)、その属性が 0x40000001、固定値の属性が 0x80000000。
- モデルは陰影を頂点カラーに焼き込んでいる (法線がない) ので、ライティングなしで描く。頂点カラーのアルファは不透明な面では使わない。
- 回転: 種類 7 (部屋の辺) の回転 0 のモデルは -Z (北) 側に壁がある。three.js では `rotation.y = -rot × 90°`。
- マップ表 (0x4C3AFC) の +0x10 (タイルセットの上書き) は、ダンジョンのマップではすべて 0 (上書きなし)。
- マップ DB のサイズ 0 のエントリは、次のブロックと同じオフセットを持つ。再構築では (オフセット, サイズ) の順に並べると元とバイト一致する。
- ダンジョン名は mapGroup +0x14 の u16 (u32 で読むと K / M / S 系が引けない)。
- オブジェクトのモデルは mapObject (マスター) の行。区画ごとの決め方、宝箱・EventObject・mapChara は `../elpulse/docs/map.md` §6・§8〜§10、実装は `src/game/objects.ts`。
- CGFX のボーンの world 行列は空のことが多いので、拡大・回転・移動を親から合成する (門の枠や宝箱のふたの位置)。
- マテリアルは PICA のテクスチャ合成 (TEV 6 段)・アルファテスト・ブレンドをシェーダーで再現する (`src/cgfx/tev.ts`)。例: ひび割れの貼り付けは乗算 (白 = 変化なし)、M_pack は 2 枚目のテクスチャの赤をアルファにしてアルファテストで抜く。フラグメントライティングは未対応 (白として扱う)。
- テクスチャのデータは上の行から並ぶが UV は v = 0 が下なので、上下を反転して渡す。

## テスト

```bash
python test/golden/export_golden.py   # ../elpulse の展開済みデータから test/golden/golden.json を作る
bun test
```

`rom.test.ts` は `ROM_CIA` (既定 `../elpulse/00040000000A7900.cia`) と `golden.json` がないときはスキップします。
- code.bin (BLZ の展開) が ctrtool の結果と一致
- 全 205 マップの名前・ダンジョン・階・区画のハッシュとサイズ、D01B02001 / D02B02002 のタイルと区画 3/4/5/8 が mapdump.py と一致
- LZ10 の圧縮結果が gsarc.lz10_compress とバイト一致
- 無編集で書き出したマップ DB・アーカイブが元とバイト一致、編集時は A2C14C00 以外のエントリが一致
- バニラのマップで検証が何も出さず、壊した編集は検出する

## 未対応・今後

- 扉・門の位置と向きは近似 (部屋の出入口のタイルでは開口側の辺に寄せる)。静止姿勢で床下にあるモデル (一部の門) は持ち上げて表示。
- 区画 5 のモンスター (mapChara の種類がモンスター)、区画 8 (イベントの範囲) は記号で表示。区画 6 / 7 / 9 の意味は未確定 (7 は保持のみ)。
- 新しい宝箱 (EventObject の行) の追加はなし。宝箱を複製すると同じ行 (中身とフラグ) を共有する (警告を出す)。
- マテリアルのフラグメントライティング、テクスチャアニメ、バッファ (TEV の前段バッファ) は未対応。
- 新しいマップの追加 (フェーズ 2、code.ips が必要) はなし。
- ゲームでの確認: タイルの変更は確認済み。宝箱の中身・イベントの表の書き出しはまだ。
