# `/stages` のスクリプトを一つのコード欄にする計画

現在は変数表と関数ごとの本文欄を編集し、`scriptDocSource()` がそれを `var`・`function`・`on` の文字列へ組み立てる。マップでのレコードへの割り当てと、入場時・開始時のプルダウンも同じ `ScriptDoc.bindings` を更新している。このため、一つのコード欄にする際は、コードと割り当て操作が同じ内容を上書きしないようにする。

1. ステージのスクリプト全体を `ScriptCodeEditor` 一つで表示する。内容は変数・関数・`on` の割り当てを含む `stored.source` とする。複数 MapGroup のイベントも同じ欄に置き、関数の波括弧で折りたためるようにする。関数の追加・例の挿入はカーソル位置または末尾にテキストを挿入する。
2. 入力中の文字列をドラフトとして保ち、コード欄からフォーカスが外れたら `scriptDocFromSource()` で解析して `setStageScriptDoc()` に反映する。解析エラーは行番号付きで欄内に示し、ドラフトを残す。明示的な「反映」と「変更を捨てる」も残す。無効なドラフトがある間は、マップのページやプルダウンからの割り当て更新でドラフトが消えないようにする。
3. マップのページや入場・開始のプルダウンが割り当てを変えた場合、未編集のコード欄は新しい `stored.source` に同期する。未反映のドラフトがある場合は自動上書きせず、割り当ての競合を示してから適用する。関数名の変更・削除と割り当ての移行は現行の `docOfDraft()` と同等に扱う。
4. 補完はカーソルを含む関数の `on` 割り当てから MapGroup を決め、台詞とイベント行をそのグループから出す。`battle()` はステージの MonsterGroup 行番号を出す。複数グループに割り当てた関数では、台詞・イベント行の補完候補にグループ名も表示する。
5. 変数・関数・割り当てをコードだけで編集する流れと、従来のプルダウンから変更する流れをそれぞれ試す。無効なコードを残してページを切り替える場合と、戦闘後の `on start` の保存・復元も確認する。
