# RPG FREE! の SE 番号と再生経路（STATE #5）

対象はローカルの Base / Update ROM。コードのアドレスは Update `code.bin` を `0x00100000` に配置した値。以下の「番号」は混同しやすいので区別する。

| 値              | 意味                             | 例           |
| --------------- | -------------------------------- | ------------ |
| SoundData 行    | MapData や `se()` が指定する番号 | `110`        |
| SoundData +0x00 | BCSAR のアイテム ID              | `0x010000BF` |
| BCSAR 音番号    | アイテム ID の下位 24 bit        | `191`        |

## 確認できたこと

- Update の SoundData 行 #107〜#111 は Base の `sound/sound.bcsar` の音番号 #188〜#192 を指し、名前は順に `SE_ILD_CHANGE`、`SE_FLD_ALERT`、`SE_FLD_FORMATION`、`SE_FLD_ENCOUNT1`、`SE_FLD_ENCOUNT2`。#110 の BCSAR 音番号は #191。
- この 5 件の BCSAR シーケンスは共通の CSEQ 内の終了命令 `0xFF` から始まる。Panana で描画した PCM も無音。したがって `/sounds` で試聴できない理由は少なくともこのローカル音源ではデータ自体にある。
- Update コード `0x003E67BC` は MapData +0x08 を読んで `0x001A0AC4` に渡す。同関数は 0 を `0x6B`（107）に置き換え、オブジェクト +0x08 に格納する。`0x001A19B0` と `0x001A19C8` はその値を読み、再生状態の照会 `0x002D76FC` と SE 再生関数 `0x002E94A8` に渡す。この経路には一定の番号を加減する変換が見当たらない。
- `0x001A19C8` に到達するまでには、`0x001A1894` 内で状態、位置、時間などの条件を判定する。MapData +0x08 を「エンカウント時に必ず鳴る音」とする根拠はない。
- `se()` は SoundData 行を引数にする。BCSAR 音番号を直接指定する文法ではない。`/sounds` の名前は BCSAR の名称と SoundData の参照先から得ており、ゲーム中でその名の音が聞こえたことを意味しない。

## 残る問題

ユーザーが実ゲームで聞いた音の発生元は未特定。MapData +0x08 と同時または近いタイミングで、別のゲームコードや CRO が SE を鳴らす可能性がある。#107〜#111 の名称から用途を推測しても、どの音が実際に聞こえるかは確定しない。次の確認には、問題が起きるマップと状況を固定し、エミュレータで SoundData 行、BCSAR アイテム ID、発音イベントの呼び出し元を同時に記録する必要がある。
