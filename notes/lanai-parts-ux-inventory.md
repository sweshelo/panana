状態は EventObject の行ごとに独立したスロットを割り当て、追加ステージの所有する state 範囲は `lanai-stage.json` に載る。ボタンの関数と割当は追加ステージの CRO に入り、配置・関連行・スクリプトはマップ編集の 1 回の Undo で戻す。新規ステージの stage key は編集中も保持する（`src/lanai/session.ts`、`src/lanai/stageScript.ts`）。

/maps のパーツ一覧は、目的別カテゴリ（扉・移動、スイッチ、宝箱・ゴール、人物・敵、メッセージ・店、範囲イベント、床のギミック）の新規パーツと、そのステージのマップにあるものの複製（「既存ギミック」にまとめる）に分ける。ワープゲート・ワープホールは記号ではなく #104 の 3D モデルで表示する。

各オブジェクトは URL のアンカー `#/maps/<コンテンツ>.<マップ>@<区画>.<番号>` を持つ。開くと対象を選んでインスペクタに出し、表示設定がオンなら 2D・3D の中心に移す。選択を変えるとアドレスも更新する。出入口の「接続」には行き先の出入口へのリンク、ここへ来る出入口の一覧、ボタンと扉の相互リンクを出す。

配置時の扉・ワープゲート・ワープホール・階段の行き先指定と、保持スイッチの開扉対象指定は任意。未接続の出入口は検査でエラーとして示し、相手を置いた後にマップのインスペクタからつなぐ。スクリプトで使う ID は MapGroup の EventObject 行番号で、出入口の到着地点 ID とは別。インスペクタ上部と配置物の一覧にイベント ID を表示する。

実機で残る受入確認は、新規ステージの扉→ボタン→階段→通常宝箱→クリア宝箱、MOD 再取込、セーブ再読込、再挑戦、本編・他ステージの状態への非干渉。現時点の自動テストはデータ生成と CRO 構築、Undo/Redo、保存・再読込を検証し、ゲーム内挙動の代わりにはしない。

スイッチの押下直後にフラグを変えても、出現条件を持つ出入口はその場で現れず、戦闘後のマップ再読込で現れた（ユーザーの実機観察）。公開されている Script API の表には `DeleteEventObject` とイベントの当たり判定切替はあるが、EventObject を再生成・出現条件を再評価する関数は見当たらない。即時出現とその演出はゲーム側の別経路を調査する必要があり、現在のスクリプト生成では保証しない。
