# FREE! パーツ配置の改善計画

## 達成する体験

「扉を置き、ボタンで開く」「宝箱を開けてクリアする」を、ROMの区画・種類・行番号やスクリプトを知らずに作れるようにする。配置前の画像、配置後の表示、ゲーム中の見た目と動作を一致させる。現在は計画段階であり、以下の機能が実装済みという意味ではない。

## 配置の流れ

一覧は「扉・移動」「スイッチ」「宝箱・ゴール」「人物・敵」「範囲イベント」「装飾」に整理する。同じ扉を別カテゴリへ重複登録しない。カードには実際のモデル、目的、短い動作説明、設定状況を表示する。未設定の画像には「見た目未設定」を表示し、別物の代替画像で埋めない。

扉は配置前に「通路をふさぐ／場所を移動する」、見た目、向き、開く条件または行き先を設定する。通路用の扉は開閉の対象として選べ、移動用は接続先をマップ上で選ぶ。階段も上り下りと接続先を指定し、未接続のまま完了させない。

ボタンは保持式か押下中のみかを明記し、操作対象の扉をマップ上で選ぶ。接続線と「このボタンで開く」表示を双方に出す。押下中だけ開く動作は、離脱通知と閉じる処理の実機検証を先に行う。未対応なら選択できない状態で理由を表示する。

宝箱は通常／クリアを選び、報酬（固定・抽選）、開封後の状態、クリア対象と再挑戦時の報酬を設定する。初回・再挑戦の既存仕様を保ち、既存ステージの設定を黙って単純化しない。

配置後のインスペクタは「見た目」「動作」「接続」「条件」を表示する。区画・行番号・動作コードは折りたたんだ詳細へ残す。関連する複数行の作成・変更は一回の Undo で戻せるようにする。

## 実装順と完了条件

1. **実データの照合と台帳**: モデル番号・名称・画像・動作・必要な関連表をROMから照合する。ボタン2種、外部操作の扉、移動扉、階段、通常宝箱、ゴール宝箱の最小例を作る。種類4/6の保持・離脱、扉の見た目0のゲーム側補完は未確認として分離する。
2. **誤認を防ぐ表示**: 装飾の明示、目的別分類、実画像、未設定表示、機能の説明を揃える。モデルが欠けた場合にも用途を誤認させない。既存データを変更しない表示改善から始める。
3. **通常宝箱・クリア宝箱の作成**: 既存の `MapParts.tsx` / `treasure.ts` を流用し、EventObject・TreasureGroup・クリア対象を一括生成する。報酬取得とステージクリアを実行確認する。
4. **扉・階段の作成**: 既存出入口の編集を流用し、配置・床・向き・見た目・接続先を一括設定する。移動先なし／存在しない接続先を検出する。
5. **ボタンと扉の連動**: `scriptDoc.ts` の `openDoor` とイベント生成を土台に、保持式を先に提供する。押下中のみは離脱・閉扉・プレイヤー挟み込みの検証後に提供する。状態は本編と他ステージから独立させ、再入場・セーブ再読込時の扱いを表示する。
6. **通しの受入確認**: 新しいステージから、ボタン→扉→階段→宝箱→クリアを作成する。各段階でUndo/Redo、保存再読込、MOD再取込を確認し、Azaharで画像・開閉・移動・報酬・再挑戦を検証する。

配置完了時に「見た目なし」「移動先なし」「操作対象なし」「報酬なし」「クリア対象なし」を検出し、該当パーツへ移動できるようにする。未確認の挙動を利用可能として表示しない。最終受入条件は、初めて使う人が種類番号の説明を読まずに上記の通しステージを完成できることとする。
