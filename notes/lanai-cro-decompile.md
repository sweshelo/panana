# 出荷 CRO のイベントをステージスクリプトへ逆変換する — 調査

2026-11-22。目的: 既存ステージのギミック・イベントを雛形としてスクリプトエディタに取り込み、カスタムイベントを書きやすくする。
材料: `lanai-custom-stages/3ds/research/event-dispatch.md`・`script-abi.md`、`out/script-abi/` の `calls.tsv`・`classes.tsv`・`factories.tsv`・`cro/*.bin`。
集計スクリプトは `roms/tmpmap/decomp/scan.ts`・`q.ts` (ROM 由来のため roms/ 下、コミットしない)。

## 1. 今の仕組み (逆変換の前提)

- 本体が CRO を呼ぶ入口は **indexed export 41 枠** と、枠が返す **EventScript 派生オブジェクトの仮想関数** だけ。
- 「どの行のイベントか」は **ファクトリ枠** (0 範囲 / 3 マップ開始 / 4 ボタン / 8 話しかけ) が `GetCurrentMapGroupID()` と EventObject の ID を if/switch で比べて決める。クラス名 (`D01001F01Gimmick001`) は照合に使われない。
- イベント本体は vtable の `+0xC Execute` (ブロッキングの直線コード)、後処理は `+0x10 CtrlFlag`、マップ読込時の準備は `+0x8`、入場演出は `+0x18`。
- Panana の言語 (`eventScript.ts`) は `on <契機>(group, row) 関数`、byte/bit 変数 (12000〜/24000〜 の専用範囲)、if/switch/return/break、Script API の名前呼出し、ライブラリ関数 (talk, walk, openDoor …) を持つ。コンパイラは同じ形 (ファクトリ → new → vtable → Execute) を生成する。
- 追加ステージの CRO は「複製元のまま ('copy'、フラグも共有)」か「空 + スクリプト ('empty')」の二択で、出荷イベントを部分的に流用する手段がない。

## 3. 逆変換で欠落しうる情報

### A. 結び付け (どの行で・いつ起きるか)

1. **生成の条件**: ファクトリがフラグを見て「作らない / 別のクラスを作る」場合 (枠 3 の 99 本)。`on` には生成条件が無いので、本体先頭の `if` に移すしかない。ただし「オブジェクトが無い」と「何もしない Execute」は同じではない (メニューが隠れる、CtrlFlag が状態を進める)。
2. **1 クラス対 複数の ID**: `switch (id - 0x10) case 0..3` のように 1 クラスを複数の行で使う形。`on` を行の数だけ並べ、行の違いは `selfRow` で書く。
3. **ファクトリがメンバーに入れる値** (例 `+0x68 = 0xB`、`NpcCommonTurn` の台詞・戻る bool、`IntroCommon` のマップ ID ハッシュ): 言語にコンストラクタ引数は無い → 定数として本体に埋め込む。
4. **言語に無い契機**: 枠 1 脱出・5 宝箱・6 扉/階段・13 常駐・2 釣り・12 船、枠 24 の全滅以外の条件 (時間切れ等)、枠 31/32、枠 26/38。これらはコメントで残すだけになる。
5. **基底クラスの Execute をそのまま使うクラス** (189、階段・穴・扉など): 動きは code.bin 側にあり、CRO にはコンストラクタ引数しか無い。データのパーツとして扱うべきで、スクリプトにする対象外。
6. **準備 (+0x8) 257 本**: マップ読込時に NPC を持ち上げる・モンスターを追従させるなど。言語に契機が無い (`start` は別物)。
7. **CtrlFlag の上書き 569 本 (269 本がメンバーを読む)**: Execute の後にフラグを書く。本体の末尾に移せばほぼ同じだが、ボス戦 (`EncountBoss` の後は走らない) で順序が変わる。
8. **+0x14 (メニューを隠すか) の上書き 107 本**。

### B. 本体の書き方

9. **ベクトル値** (`GetPos`・`GetShadowPos`・`VECAdd/Subtract/SquareMag`、向き・距離の計算): 言語に vec の変数・演算が無い。最多の欠落。
10. **数値の局所変数・浮動小数の計算** (313 / 208 本): byte 変数は 0〜255 の保存フラグなので代わりにならない。
11. **メンバー変数** (派生フィールド 588 本): Execute 内の受け渡しなら局所変数、CtrlFlag や次回実行への受け渡しなら保存されない状態になる。
12. **他のオブジェクト型**: `ScriptMonster` (312)、`ScriptEffect` (vanishEffect だけある)、テロップ (`ClearTelop`/`RetireTelop`)、`RareItemDirection`、`ScriptMenuParam` 派生、表 (`GSdbAccessor::GetRecord`)、アーカイブの読込み。
13. **基底クラスのメンバー関数**: `TurnNpc`/`TurnHero`/`TurnNpcRecover`、`ZoomHeroCamera`/`RecoverHeroCamera`、`GetActionBeforePos`/`ActionAfterMove`。Script API 表に無い。
14. **隊列のループ** (461): `ScriptPlayer[8]` と `for i < GetPlayerNum()` は、言語では `hero` しか書けない。定型として畳むか、ライブラリ関数を増やす。
15. **ヘルパー関数** (238): インライン展開するか、引数付きのスクリプト関数にする。後者なら読みやすい。
16. **仮想呼出し・関数ポインター (186)、静的データ (32)**: 機械的には復元できない。コメントで残す。
17. **型の手がかり**: bool / 列挙 (`GSAnimMode` など) / 行 ID (`0x800000NN`) は数値でしか残らない。引数名は API 表のシグネチャで補う。

### C. 雛形として別ステージへ持ち込むとき (識別子)

18. **フラグ番号**: 出荷 CRO はセーブ全体で共有のフラグ (例 byte 0x69、bit 0xB1) を直接使う。スクリプトの変数は宣言順に専用範囲へ割り当てるので、元の番号は消える。データ側 (EventObject の出現条件・ボス戦の動作の引数) も同じ番号を参照しているため、両方を同時に付け替えないと条件が切れる。変数名は元の番号から機械的に付けるしかない。
19. **EventObject の行 ID** (`obj(N)`・`GetScriptState(N)`・`DeleteEventObject(N)`・`SetDoorOpenFlag(N)`)、**台詞の行 ID** (元のグループの会話表)、**マップ ID ハッシュ** (`ChangeMap`)、`SetNextMapEvent` の番号、**マップグループ番号**: どれも複製元のデータを指す。複製したステージなら一致するが、別ステージへ移すと付け替えが要る。
20. **座標** (`vec(x, y, z)`): 元マップの配置に依存する。
21. **名前・注釈**: 元のソースの変数名・コメントはもともと無い。クラス名 (`D01001F01Gimmick001`) と RTTI だけが残るので、関数名に使える。
22. **コンパイラの最適化で畳まれた式** (`π/180` の掛け算、比較の合成): 定数のまま出る。

## 4. 方針の案

- 出力は「**そのまま再コンパイルできる部分** + **できない部分は `// 未対応: …` の注釈**」の雛形とする。完全な往復 (バイト一致) は目指さない。
- 段階:
  1. 結び付けの復元: ファクトリ枠 0/3/4/8 を記号実行し、(グループ, ID, 生成条件) → クラスの表を作る。`on` 行と関数の骨組みを出す。
  2. 本体の復元: Execute を基本ブロックに分け、import 呼出しの列 + 比較・分岐 (if/else、switch) + フラグの読み書きを `ScriptNode` にする。`ScriptChara(GetMapChara(N))` → `obj(N)`、`GetPlayerHero` → `hero`、`this+0xC` → `self`、SMP {0,0} → `0`。
  3. 定型の畳み込み: 隊列ループ、`talk`・`walk`・`open`・`jingle`・`openDoor`・`vanish` などのライブラリ形、CtrlFlag の末尾移し。
  4. 識別子の付け替え: 使っているフラグを変数として宣言し、元の番号を注釈に残す。行 ID・台詞・マップは元の値のまま出し、付け替えは作者に任せる。
  5. UI: スクリプトエディタで「既存のイベントから挿入」(コンテンツ → クラスを選ぶ → 本体を関数として挿入)。
- 言語の拡張 (別タスク): vec の局所変数と `GetPos`、数値の局所変数、`TurnNpc`/`TurnHero` などの基底メソッド。最も多くを救えるのは **ベクトル値 + 局所変数** (表 B-9・10)。
