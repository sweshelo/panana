# Lanai のステージ編集・条件スクリプト

対象は日本版 FREE! Base v0 + Update v17408。[naauao PR #77](https://github.com/sweshelo/naauao/pull/77) の条件解析を参照。ROM のデータは追加していない。

## ステージの解放条件

`MapStage` と `MapStageIntegration` の +0x1C / +0x20 は表示条件の引数 1 / 2、+0x24 の下位 1 バイトは条件の種類。従来の資料の「分類 (推定)」は誤り。+0x28 / +0x2C / +0x30 は非表示条件。上位の 0xD0 パディングは残す。

- `FUN_001D6CD4` の +0x34 のステージ枠を解決する部分で、スロット先頭 +0x0C が表示情報へのポインターになる (`@0x1D6D38`)。
- `@0x1D6D3C..64` は MapStage +0x1C/+0x20/+0x24 をスロット先頭 +0x124/+0x128/+0x12C にコピーする。表示情報からのオフセットは **+0x118/+0x11C/+0x120**。+0x28/+0x2C/+0x30 は表示情報 +0x124/+0x128/+0x12C にコピーされる。12 バイトの先頭の差に注意。
- `FUN_002A9024` は表示情報 +0x118 と +0x124 をそれぞれ `FUN_002FCD38` に渡し、**表示条件 AND NOT 非表示条件** を返す。種類 0 の既定値は表示側が 1、非表示側が 0。
- 例: コンテンツ 2「オリバの木工工房」は表示条件が種類 3、引数 17 / 1。セーブ 0x51[17] が非ゼロなら表示。種類 3 は引数 2 を使わない。コンテンツ 3 はフラグ 18。
- 種類 0x16 はタイマーの残り時間。判定はタイマーを開始しない。配信一覧、期限やペナルティ、CRO のコールバックなど、別経路の制御をこの条件編集で解除するわけではない。

`test/lanai-stageedit.test.tsx` は実 ROM の `FUN_001D6CD4` を実行し、文字列のコピーだけをスタブにして条件のコピー先を確認し、続けて `FUN_002A9024` と実際の条件分岐を実行する。フラグの読み出しだけを差し替え、未解放・解放・非表示の優先を確認する。実機での検証ではない。

## 条件スクリプト

ステージの表示・非表示条件と、マップのイベントの出る・消える条件から使う。

```
flag(17) && !cleared(1)
valueGe(23, 3) || (timer(102) && eventLe(7, 1))
```

構文は `true`, `false`, `!`, `&&`, `||`, 括弧と、`cleared`, `flag`, `valueEq/Ge/Le`, `eventGe/Le`, `timer`。数値は十進または `0x` から始まる十六進。条件番号は u16、比較値は u32。`eventGe/Le` は現在の MapGroup のイベント状態を読むので、ステージ選択画面など現在のグループがない場所では偽になる。

パーサーは JavaScript を実行しない。ネイティブの条件判定関数 `FUN_002FCD38` の先頭をコード領域の分岐へ差し替え、未使用の種類 0x72 + 引数 1 のスクリプト番号を処理する。元の種類 0〜0x71 は元の処理へ戻す。葉の条件は元の判定関数を呼び、AND/OR は短絡評価する。スクリプトの未知番号は偽。追加コードは既存の patch assembler を通し、`exefs/code.ips` に入る。既存のドロップ率 MOD とコード領域を分け合うため、空き領域を超えると書き出しを拒否する。既存 MOD が判定関数の先頭を変更していた場合も拒否する。

スクリプトは既存 CRO の生成・置換ではない。CRO がコールバック 0x1F / 0x20 でイベント条件を上書きした場合は CRO が優先される。既存 CRO を自由な TypeScript に逆コンパイルしたり、`ScriptMenu::StartMessage` 等の任意の動作・待機・移動を生成する機能は未対応。

## Script API の調査

ステージ詳細のリファレンスは Update の `app/lanai.crs` の named export テーブルを読む。Update の app と .crr は patchList に載らないため、通常の Base/Update 合成とは別に Update 内のリソースを読む。Base の CRS を Update のアドレスとして扱わない。

named exports は +0xD0 / +0xD4、segment table は +0xC8 / +0xCC。名前のオフセットはファイル絶対位置。アドレスは export の下位 4 ビットでセグメントを選び、残りの上位ビットをセグメント開始に加える。オーバーロードを失わないよう、生の C++ シンボルと解決したアドレスを保持する。引数型は生の Itanium ABI シンボルに残り、全 API の意味やコルーチンの呼出規約が検証済みという意味ではない。

確認済みの例:

| API                                           | Update のアドレス | 用途                           |
| --------------------------------------------- | ----------------- | ------------------------------ |
| ScriptFlag::GetScriptBitFlag(unsigned short)  | 0x2E7DF4          | セーブ 0x51 のフラグ           |
| ScriptFlag::GetScriptByteFlag(unsigned short) | 0x2FF158          | セーブ 0x52 の u8 数値         |
| ScriptFlag::IsClearMapGroup(unsigned short)   | 0x2F4B58          | セーブ 0x53 のクリア状態       |
| ScriptFlag::GetScriptState(unsigned int)      | 0x2C7028          | 現在の MapGroup のイベント状態 |

## コンテンツの追加

「コンテンツを複製して追加」は、単一ステージのコンテンツをひな形にする実験機能。

- 元の現在の編集を含め、空きのルートファイルにアーカイブをコピー。アーカイブヘッダーのハッシュも新しいものにする。
- Contents を追加し、ContentsDef の先頭 2 行を新しいコンテンツ番号にする。
- MapStageIntegration / MessageMapStage を追加。メッセージ ID とコンテンツ番号を更新し、MapStage にも反映。ステージの枠番号 (+0x34、Integration +0x40) は最大値 +1 とし、既存枠に重ねない。
- 既知のゴール宝箱・クリアワープが元のコンテンツ自身を指していた場合と、EventObject の自コンテンツのクリア判定を新しい番号へ変更する。
- CRO は同じバイトのまま保持。そのハッシュに対応する **Update の CRR** を新しいコンテンツの CRR パスへコピー。CRO のバイトを書き換えず、CRR の再署名はしない。複製前に CRO の先頭 0x80 バイトの SHA-256 が CRR に登録されているか検査する。
- MOD に新しいアーカイブ、CRR、既存の配信リストに新しいアーカイブを加えた patchList.bin と変更した master を入れる。編集データの保存・復元・全体のリセットに新規ファイルも含める。

**未確認**: コンテンツ数・ステージ枠のゲーム側の上限、ローダーが別番号で元の名前の CRO を受け入れるか、新しいコンテンツが実機で選択・起動できるか。CRO 内でハードコードされた番号やフラグ、独立したセーブ領域の確保は自動変換しない。このため「追加しただけで独立して遊べる」ことは保証していない。

## 追加したステージのマップ・始まり・最初のイベント

[naauao contents.md §3.3 / §4.2](https://github.com/sweshelo/naauao/blob/claude/project-thread-sedcfz/lanai/contents.md) の解析をもとにする。

- **マップを開けなかった不具合**: ページは別のタブを開いても残るので、マップのページなどが最初に読んだコンテンツの一覧を使い続け、追加したコンテンツ 127 のマップを開くとコンテンツ 1 になっていた。`useLanaiContents` (`src/lanai/useContents.ts`) が Contents と MapStageIntegration の行数が変わったときに一覧を読み直す。追加を取り消して同じ番号で作り直したときは、マップのキャッシュ (`lanaiMaps`) も読み直す。
- **ステージの始まり**: ステージの詳細の「ステージの始まり」で最初のマップと到着する出入口を選ぶ。MapStage +0x3A (MapStageIntegration +0x46) をそのマップの MapGroup にし、MapGroup +0x14 / +0x18 にマップのハッシュと地点 ID を書く。ROM の 126 ステージすべてで、この組が自分のマップ表の出入口を指すことをテストで確かめている。
- **最初のイベント**: 本体は CRO の indexed export を番号で呼び、3 番がフィールドの開始時のイベントを返す。CRO は署名つきの CRR に登録されているので書き換えない。「コンテンツを複製して追加」で「イベントなし」を選ぶと、イベントのクラスを持たないコンテンツ 99 の CRO と `contents0099.crr` をそのまま使う。開始の演出・会話・CRO のギミックはなくなり、マップ・宝箱・出入口・クリアは表のデータで動く。元のまま写すと、CRO が読むフラグ (例 0x24) を元のステージと共有する。
- **未確認**: ゲーム内での起動。セーブの 0x27 / 0x28 が 0 のときに MapGroup の最初のマップを使う処理は追っていない (データの照合による)。別番号のコンテンツで `contents0099` のモジュール名の CRO を読み込めるか。

## メッセージへの挿入

Lanai の共通メッセージエディタに「＋ アイテム名を挿入」「＋ 表の文字列を挿入」を追加。選択範囲を `{ins:ItemData:0x80000001:name}` のような参照へ置き換え、プレビューして反映する。アイテムは検索付きモデル画像のグリッドで選ぶ。表と欄を選ぶ汎用の挿入もある。自由入力中の `ins:` 自動補完は未実装。

## 再現

```
bun scripts/research/lanai-stages.ts
bun scripts/research/lanai-stages.ts --api
bun scripts/research/lanai-stages.ts --disasm
bun test test/lanai-stageedit.test.tsx
bun run typecheck
bun run build
```

`roms/lanai-base.cia` と `roms/lanai-update.cia` が必要。ROM がない場合は ROM テストをスキップする。

ブラウザでも実 ROM を開き、ステージ条件・スタミナの保存、選択位置への画像グリッドからのアイテム名挿入、コンテンツ 127 の追加、MOD ZIP のダウンロードを確認。ゲーム本体での実行確認ではない。
