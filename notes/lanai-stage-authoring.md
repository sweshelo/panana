# Lanai のステージ編集・条件スクリプト

対象は日本版 FREE! Base v0 + Update v17408。[naauao PR #77](https://github.com/sweshelo/naauao/pull/77) の条件解析を参照。ROM のデータは追加していない。

## ステージの解放条件

`MapStage` と `MapStageIntegration` の +0x1C / +0x20 は表示条件の引数 1 / 2、+0x24 の下位 1 バイトは条件の種類。従来の資料の「分類 (推定)」は誤り。+0x28 / +0x2C / +0x30 は非表示条件。上位の 0xD0 パディングは残す。

- `FUN_001D6CD4` の +0x34 のステージ枠を解決する部分で、スロット先頭 +0x0C が表示情報へのポインターになる (`@0x1D6D38`)。
- `@0x1D6D3C..64` は MapStage +0x1C/+0x20/+0x24 をスロット先頭 +0x124/+0x128/+0x12C にコピーする。表示情報からのオフセットは **+0x118/+0x11C/+0x120**。+0x28/+0x2C/+0x30 は表示情報 +0x124/+0x128/+0x12C にコピーされる。12 バイトの先頭の差に注意。
- `FUN_002A9024` は表示情報 +0x118 と +0x124 をそれぞれ `FUN_002FCD38` に渡し、**表示条件 AND NOT 非表示条件** を返す。種類 0 の既定値は表示側が 1、非表示側が 0。
- 例: コンテンツ 2「オリバの木工工房」は表示条件が種類 3、引数 17 / 1。セーブ 0x51[17] が非ゼロなら表示。種類 3 は引数 2 を使わない。コンテンツ 3 はフラグ 18。
- 種類 0x16 はタイマーの残り時間。判定はタイマーを開始しない。配信一覧、期限やペナルティ、CRO のコールバックなど、別経路の制御をこの条件編集で解除するわけではない。

`test/lanai-stageedit.test.tsx` は実 ROM の `FUN_001D6CD4` を実行し、文字列のコピーだけをスタブにして条件のコピー先を確認し、続けて `FUN_002A9024` と実際の条件分岐を実行する。フラグの読み出しだけを差し替え、未解放・解放・非表示の優先を確認する。実機での検証ではない。

## 条件スクリプト

ステージの表示・非表示条件と、マップのイベントの出る・消える条件から使う。

```
flag(17) && !cleared(1)
valueGe(23, 3) || (timer(102) && eventLe(7, 1))
```

構文は `true`, `false`, `!`, `&&`, `||`, 括弧と、`cleared`, `flag`, `valueEq/Ge/Le`, `eventGe/Le`, `timer`。数値は十進または `0x` から始まる十六進。条件番号は u16、比較値は u32。`eventGe/Le` は現在の MapGroup のイベント状態を読むので、ステージ選択画面など現在のグループがない場所では偽になる。

パーサーは JavaScript を実行しない。ネイティブの条件判定関数 `FUN_002FCD38` の先頭をコード領域の分岐へ差し替え、未使用の種類 0x72 + 引数 1 のスクリプト番号を処理する。元の種類 0〜0x71 は元の処理へ戻す。葉の条件は元の判定関数を呼び、AND/OR は短絡評価する。スクリプトの未知番号は偽。追加コードは既存の patch assembler を通し、`exefs/code.ips` に入る。既存のドロップ率 MOD とコード領域を分け合うため、空き領域を超えると書き出しを拒否する。既存 MOD が判定関数の先頭を変更していた場合も拒否する。

スクリプトは既存 CRO の生成・置換ではない。CRO がコールバック 0x1F / 0x20 でイベント条件を上書きした場合は CRO が優先される。既存 CRO を自由な TypeScript に逆コンパイルしたり、`ScriptMenu::StartMessage` 等の任意の動作・待機・移動を生成する機能は未対応。

## Script API の調査

ステージ詳細のリファレンスは Update の `app/lanai.crs` の named export テーブルを読む。Update の app と .crr は patchList に載らないため、通常の Base/Update 合成とは別に Update 内のリソースを読む。Base の CRS を Update のアドレスとして扱わない。

named exports は +0xD0 / +0xD4、segment table は +0xC8 / +0xCC。名前のオフセットはファイル絶対位置。アドレスは export の下位 4 ビットでセグメントを選び、残りの上位ビットをセグメント開始に加える。オーバーロードを失わないよう、生の C++ シンボルと解決したアドレスを保持する。引数型は生の Itanium ABI シンボルに残り、全 API の意味やコルーチンの呼出規約が検証済みという意味ではない。

確認済みの例:

| API                                           | Update のアドレス | 用途                           |
| --------------------------------------------- | ----------------- | ------------------------------ |
| ScriptFlag::GetScriptBitFlag(unsigned short)  | 0x2E7DF4          | セーブ 0x51 のフラグ           |
| ScriptFlag::GetScriptByteFlag(unsigned short) | 0x2FF158          | セーブ 0x52 の u8 数値         |
| ScriptFlag::IsClearMapGroup(unsigned short)   | 0x2F4B58          | セーブ 0x53 のクリア状態       |
| ScriptFlag::GetScriptState(unsigned int)      | 0x2C7028          | 現在の MapGroup のイベント状態 |

## コンテンツの追加

「コンテンツを複製して追加」は、単一ステージのコンテンツをひな形にする実験機能。

- 元の現在の編集を含め、空きのルートファイルにアーカイブをコピー。アーカイブヘッダーのハッシュも新しいものにする。
- Contents を追加し、ContentsDef の先頭 2 行を新しいコンテンツ番号にする。
- MapStageIntegration / MessageMapStage を追加。メッセージ ID とコンテンツ番号を更新し、MapStage にも反映。ステージの枠番号 (+0x34、Integration +0x40) は最大値 +1 とし、既存枠に重ねない。
- 既知のゴール宝箱・クリアワープが元のコンテンツ自身を指していた場合と、EventObject の自コンテンツのクリア判定を新しい番号へ変更する。
- CRO は同じバイトのまま保持。そのハッシュに対応する **Update の CRR** を新しいコンテンツの CRR パスへコピー。CRO のバイトを書き換えず、CRR の再署名はしない。複製前に CRO の先頭 0x80 バイトの SHA-256 が CRR に登録されているか検査する。
- MOD に新しいアーカイブ、CRR、既存の配信リストに新しいアーカイブを加えた patchList.bin と変更した master を入れる。編集データの保存・復元・全体のリセットに新規ファイルも含める。

**未確認**: コンテンツ数・ステージ枠のゲーム側の上限、ローダーが別番号で元の名前の CRO を受け入れるか、新しいコンテンツが実機で選択・起動できるか。CRO 内でハードコードされた番号やフラグ、独立したセーブ領域の確保は自動変換しない。このため「追加しただけで独立して遊べる」ことは保証していない。

## 追加したステージのマップ・始まり・最初のイベント

[naauao contents.md §3.3 / §4.2](https://github.com/sweshelo/naauao/blob/claude/project-thread-sedcfz/lanai/contents.md) の解析をもとにする。

- **マップを開けなかった不具合**: ページは別のタブを開いても残るので、マップのページなどが最初に読んだコンテンツの一覧を使い続け、追加したコンテンツ 127 のマップを開くとコンテンツ 1 になっていた。`useLanaiContents` (`src/lanai/useContents.ts`) が Contents と MapStageIntegration の行数が変わったときに一覧を読み直す。追加を取り消して同じ番号で作り直したときは、マップのキャッシュ (`lanaiMaps`) も読み直す。
- **ステージの始まり**: ステージの詳細の「ステージの始まり」で最初のマップと到着する出入口を選ぶ。MapStage +0x3A (MapStageIntegration +0x46) をそのマップの MapGroup にし、MapGroup +0x14 / +0x18 にマップのハッシュと地点 ID を書く。ROM の 126 ステージすべてで、この組が自分のマップ表の出入口を指すことをテストで確かめている。
- **最初のイベント**: 本体は CRO の indexed export を番号で呼び、3 番がフィールドの開始時のイベントを返す。CRO は署名つきの CRR に登録されているので書き換えない。「コンテンツを複製して追加」で「イベントなし」を選ぶと、イベントのクラスを持たないコンテンツ 99 の CRO と `contents0099.crr` をそのまま使う。開始の演出・会話・CRO のギミックはなくなり、マップ・宝箱・出入口・クリアは表のデータで動く。元のまま写すと、CRO が読むフラグ (例 0x24) を元のステージと共有する。
- **未確認**: ゲーム内での起動。セーブの 0x27 / 0x28 が 0 のときに MapGroup の最初のマップを使う処理は追っていない (データの照合による)。別番号のコンテンツで `contents0099` のモジュール名の CRO を読み込めるか。

## ステージ画像・推奨レベルと階層の追加

- ステージ編集で推奨レベルとサムネイルを変更できる。推奨レベルは `MapStage +0x36` / `MapStageIntegration +0x42` の u16。0 はレベル表示なし。既存のステージ画像を選ぶと、対象コンテンツの `+0x04` が指すレイアウトを画像リソースごとコピーする。画像だけの変更も保存・復元・MOD 書き出しの対象になる。任意の PNG/JPEG の取り込みは未対応。
- `/maps` のダンジョン追加・複製は、現在のステージ内に MapGroup とマップを作る機能。階層の追加とは別に、1 ステージ内に複数のダンジョンを配置する用途がある。
- 追加階層の空の区画にも、Map DB の索引項目が必要。実 ROM の通常マップ 553 件では、マップ表の slot 0〜8 がすべて索引に存在し、データのない区画は長さ 0 で登録されている。slot 9 はこの対象に含めない。
- Update の区画検索 (`0x2B164C`、`0x2B177C` / `0x2B17D0`) は lower_bound の検索結果についてハッシュの一致を検査しない。項目を省くと、別区画のポインター・サイズを返し得る。新規階層の生成では空の項目も登録し、以前の編集データや MOD の欠落も復元・書き出し時に補う。

これらはローカル ROM と ARM 実行テストで検証する。実機のマップ遷移・下画面ミニマップの表示確認とは区別する。

### 追加階層での CRO 開始イベントのクラッシュ (2026-11-11)

最新の `denpa-free-mod(1).zip` を Azahar の通常コンテンツ 1 に重ねた再現では、追加した `D01001B03` (`191CA8AD`、MapGroup 1) の slot 0〜8 はすべて Map DB の索引に存在した。区画 6 も元の B01 と同じ 480 バイトで、今回のログは上記の空項目欠落とは別の原因を示した。

- 再起動後の最新ログは `PC=0`、`LR=0x002ECC48`。`ScriptChara::GetAnimationEndFrame` (`0x2ECC24`) が保持するキャラポインターは 0 で、仮想関数の呼び出し先も 0 だった。
- `contents0001.cro` のロード先は `0x00770000`。スタックの `0x00770DC0` は CRO の唯一の `GetAnimationEndFrame` 呼び出し (`+0xDBC`、戻り先 `+0xDC0`) と一致する。直前は `ScriptMap::GetMapChara(29)` → `ScriptMonster` の構築 → アニメーション `0x80000066` の取得。内部再配置と vtable/RTTI の照合により、この実行関数 (`+0xD18`) は **`D01BossWin`** と特定できる。
- 開始イベントの hook 3 (`CRO +0x68C`) は MapGroup が 1、bit flag `0x24` が非ゼロ、byte flag `0x49` が 2 のとき `D01BossWin` を返す。この分岐はマップのハッシュを検査しない。
- `GetMapChara` (`0x2AC740`) は配置済みオブジェクトの識別値 (`+0x58`) を探し、なければ 0 を返す (`0x269E58` / `0x2D7928`)。元の B02 には EventObject 29 を持つボスがあるが、追加 B03 のキャラは EventObject 40〜43 のみで、29 は存在しない。

したがって、元のグループ内へ追加した階層でも、元マップのボスを前提にする CRO の開始イベントが発火し、存在しないキャラを参照していた。単に「名前の違う写しでは固有スクリプトが動かない」とする説明は不十分だった。EventObject のスクリプト動作の件数にも、別経路で呼ばれる開始イベントは含まれない。CRO のバイトやフラグを一律に書き換えることと、追加マップに限定して開始イベントを抑制することは区別する。

対策は `src/lanai/fieldStart.ts`。追加した通常マップの未使用 slot 9 に `0x504E4653` を記し、本体の開始イベント呼び出し (`0x18236C`) で、そのマップの hook 3 だけを抑制する。元のマップとワールドマップは従来の処理を呼ぶ。CRO・CRR のバイトは変更しない。保存・復元、元 ROM と一致する CRO を持つ旧 MOD の追加行にも対応し、必要な保護を `exefs/code.ips` に含める。HTTP 配信側の `3ds/build.ts` も同じ静的パッチを組み込み、既存ランタイムとの領域重複と元 ROM のバイトを検証する。

通常 MOD の確認では、書き出した `romfs` と `exefs/code.ips` の両方を適用する。HTTP 配信では、このガードを含むクライアントのパッチを先に導入しておく。ステージの ZIP を取り込み直すだけでは、実行中の本体コードは更新されない。

2026-11-11、ユーザーが Azahar で追加マップへの移動時にクラッシュしなくなったことを確認した。ただし、戻り階段でボス前へ出て元のボス撃破後イベントが始まった。元マップでは今回の保護が開始イベントを維持するため、ステージ全体のイベント独立化は未達。到着地点の問題とイベント発火は分けて調査する。配置・検証・次のイベント制御基盤の目標は [作業ログ](lanai-event-authoring-worklog.md) に記録した。

## イベントのスクリプト (2026-11-14)

追加したステージのイベントは、ステージのページの「イベントのスクリプト」で書き、MOD の書き出しでステージの CRO (ネイティブコード) になる。仕様と根拠は lanai-custom-stages の `docs/native-events.md` §7、`3ds/research/script-abi.md`。**ゲーム内では未確認** (ARM 実行器で呼出し列と引数を確かめたところまで)。

- 1 関数 = 1 イベント。変数は表、関数は 1 つずつの欄で書き、「スクリプトを反映」する。保存の形は `ScriptDoc` (`eventScript.ts`)。
- 割り当てはマップのページのレコードで選ぶ (`EventScriptBinding.tsx`)。きっかけはレコードの区画と種類で決まる: キャラ = 話しかけたとき、範囲 = 入ったとき / モンスターを倒しきったとき、ボタン (区画 5 種類 4〜6) = 踏んだとき。割り当てると動作 1 が「2D: スクリプト (CRO)」になる。「マップが始まるとき」はステージのページで MapGroup ごとに選ぶ。
- 書ける文は `scriptDoc.ts` の `SCRIPT_WORDS`。ゲームの Script API は `ScriptSound.Play(0x84, 0)` や `hero.SetVisible(0)` の形で名前で呼べる (`scriptApiTable.ts`。lanai-custom-stages の `3ds/research/script-api-table.ts` が書く生成物なので手で編集しない)。
- 例は `SCRIPT_SAMPLES` (ボタンを押したら扉が開く / モンスターと会話し、戦闘に移る)。
- 戦闘は `battle(群れの行番号)` でイベントが終わり、勝つとマップの始まりからやり直しになる。続きは「マップが始まるとき」の関数に書く。
- 関数の本文のエディタは CodeMirror 6 (`ScriptCodeEditor.tsx` が `scriptCodeMirror.ts` を動的に読む。読めるまでとテストでは textarea)。色・補完・エラーの場所・台詞の本文・折りたたみの元は `scriptAssist.ts` で、コンパイラと同じ表 (`SCRIPT_RESERVED`・`SCRIPT_WORDS`・`scriptApiTable.ts`) を読む。語を足すときは `SCRIPT_WORDS` に足せばエディタにも出る。補完: 文の名前、`クラス.` の後の関数、変数、`talk(` の中で台詞 (本文で探すと行 ID が入る)、`chara(` などの中でレコード。
- 未対応: 扉・宝箱のきっかけ、1 体ごとの撃破。

### 入場の演出 `on intro(グループ)` (2026-11-14)

コンテンツ 99 の空の CRO では、入場時のステージ名と「門の外から歩いて入り、門が閉まる」演出が欠ける。ROM の 106 クラス (`IntroCommon` 派生、CRO 28 `D01Intro` など) の定型をそのまま生成する。根拠は lanai-custom-stages の `3ds/research/stage-intro.md`。**ゲーム内では未確認** (ARM 実行器と実データの照合まで)。

- `on intro(1) {}` (演出だけ) / `on intro(1) 関数` (演出のあと、仲間が隊列に戻る前に関数)。ステージのページの「ステージに入ったとき (入場の演出)」で MapGroup ごとに選ぶ。「コンテンツを複製して追加」で「イベントなし」を選ぶと、既定で開始の MapGroup に `on intro(…) {}` を付ける (チェックで外せる)。
- 演出の形はデータから決まる (`groupOpening`、`stageScript.ts`): MapGroup の最初のマップ (+0x14) で `IntroCommon` を作り、開始地点 (+0x18) の出入口 (区画 3) のマスと向きで歩き込む (ROM の 91 / 91 件で、`GetActionBeforePos` のマスが開始地点の出入口と一致。向きは出入口の向きの逆: 1↔4、2↔8)。出入口が門 (種類 12) なら、そのイベント行の扉を読込時に開け (0x8000006E)、歩き込んだ後に閉める (音 0x7A、0x80000074)。開始地点が出入口でなければ、明るくしてステージ名だけ。
- 1 回の訪問で 1 回: ステージの bit 変数の後ろに 1 つ bit を取り、CtrlFlag で立て、ステージを離れるとき (枠 27) に戻す (CRO 28 の bit 0xB1 と同じ)。マップを出入りしただけでは出ない。演出が出た回は同じグループの `start` は作られない (枠 3 は 1 つしか返せない。次のマップ開始から `start`)。
- 試す: lanai-custom-stages の `bun web/tools/script-zip.ts --sample intro` (`stage-intro-28.zip`)。

### イベントを持つものの配置・範囲の当たり判定・battle() (2026-11-14)

- **配置**: マップのページの「パーツを選ぶ」に「イベント (新しく置く)」を足した (`eventParts.ts`)。ボタン (区画 5 種類 4 / 6、EO +0x5A = MapObject 74〜76・83 / 699・71)、キャラ (区画 5 種類 0 / 1、EO +0x5A = コンテンツの MapChara の行)、範囲 (区画 8 の矩形・円) を、新しい EventObject 行 (行 0 の写し + 動作 1 = 2D + 見た目 + 自分の状態の枠) 付きで置く。これまでは同じ MapGroup のレコードの写ししか置けず、ボタンや範囲のないステージには置く手段がなかった。置物 (区画 2) はイベントを持たない。
- **範囲の当たり判定** (`rangeShape.ts`。Update の `0x450324` が区画 8 から作り、`0x20F7D8` → `0x450018` で判定。codex による静的解析): +0x1D が 0 なら円 (中心 50 + 100 × (x + ずれ)、半径 100 × EO +0x5A。+0x14 / +0x18 は読まない)、0 以外はすべて軸に平行な矩形 (北西の角 100 × (x + ずれ)、+50 なし、全幅・全奥行き 100 × +0x14 / +0x18)。向き (+0x1C) では回らない。1 マス = 500。判定はパーティの位置 1 点で、出入りの区別はない (毎回の判定で中にあれば当たる)。種類 100 以上・EO 行 0・出現しないイベントは範囲を作らない。EO +0x5C bit15 が立つ範囲は判定のチャンネル 1 で、歩きの判定 (チャンネル 2) では当たらない。マップの 2D 表示 (半透明の形) と 3D 表示 (高さ 300 の半透明の紫の壁。円は円筒、矩形は 4 面。位置の球の代わり)、インスペクターに形を出す。
- **battle()**: `ScriptMap::EncountBoss` の群れは master +0x1068 (`_ENCOUNT` の 2 つ目。1 つ目 +0x1040 は master の `Encount` 1 行) で、`FUN_0031C038` が 0x80000000 未満を行番号、以上を行 ID として引く。ボスの範囲 (型 0C) は `0x2E281C` で u16 の行番号を渡す。MonsterGroup の行 ID は行番号と一致しない (コンテンツ 1: 0x80000000, 0x80000010, 0x80000011 …) ため、旧ビルドの `battle(5)` → `0x80000005` は見つからず行 0 (空の群れ) になっていた。行番号をそのまま渡すように直し、ない行は書き出し前に問題として出す。lanai-custom-stages の `stage-script-events.test.ts` は旧来の `群れ | 0x80000000` を期待しているので合わせて直す必要がある。
- **after_battle**: 関数の欄に「MapGroup n が始まるとき (戦闘のあとも)」のチェックを足した (ステージのページ下部の選択と同じ割り当て)。

## ステージのインポートとリリース用 zip (2026-11-25)

- **配信用 zip にスクリプトを入れる**: `panana-stage-source.json` (`romfs/` と同じ階層) に、スクリプトのあるステージごとに `{ archive, stageKey, doc }` (エディタの ScriptDoc) をコンテンツ番号で入れる。uwapo は `romfs/` の外のこのファイルを「other」として扱うだけ。
