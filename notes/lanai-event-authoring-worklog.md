- `src/lanai/fieldStart.ts` を追加。追加した通常マップの slot 9 に `0x504E4653` を記し、本体の `0x18236C` でそのマップの CRO 開始フック 3 を抑止する。元マップとワールドマップの開始イベントは維持する。CRO・CRR のバイトは変更しない。
- 追加マップの識別とガードは、新規生成・保存復元・既知の元 ROM の CRO に基づく旧 MOD の追加行に対応する。既に同一ガードを含む基盤パッチは再利用する。書き出し画面にも `exefs/code.ips` が必要なことを表示する。

## Azahar への配置と確認結果

ユーザーの指示に従い、再配信用の修復 ZIP は作成していない。最新の通常ステージ用 MOD を対象としてテスト用配置を行った。

- 対象: `C:/Users/sweshelo/AppData/Roaming/Azahar/load/mods/0004000000125D00/`
- `romfs/5EFC0000`: 追加 B03 (`191CA8AD`) の保護マークのみ変更。ほかの展開済みエントリが同一であることを検証。
- `exefs/code.ips`: 既存 HTTP 機能を保持したガード付きパッチを配置。サイズ 10,175 バイト。
- 元ファイルのバックアップ: 上記 MOD ディレクトリの `backups/before-added-floor-start-1794405888446/`。`romfs/5EFC0000` と `exefs/code.ips` を保存。
- 配信側の通常ビルド出力 `3ds/out-all/code.ips` もガード付きへ更新済み。

**ユーザーの Azahar 確認結果**:

1. 階段を下り、追加した新しいマップへ移動してもクラッシュしなくなった。
2. 追加マップから階段を上ると、ボスの目の前へ出た。
3. そこでボスを倒した後のイベントが始まった。

この結果で確認できたのは、追加マップのクラッシュ回避。ステージのイベント全体の独立化は未達。元マップへの帰還時には、今回のガードの対象外である元 CRO の開始イベントが実行され得る。ボス前への到着については、復路のマップハッシュ・入口 ID とイベントによる移動を別々に照合する必要があり、原因はまだ確定していない。

3DS 実機での今回の修正確認、HTTP 配信経由の今回の修正確認、ミニマップの階段アイコン欠落の解消は未確認。

## 現在の制約

- EventObject の定型アクション、出現条件、一部のフラグ条件は編集できる。
- CRO のクラス・使用 API の表示はあるが、全イベントの発火条件、処理順序、フラグの読み書きを網羅した一覧はない。
- 条件スクリプトは判定用。任意のフラグ書き込みや、会話・移動・戦闘・待機などのイベント列を作者が自由に生成する機能は未実装。
- 複製元のネイティブコード、グローバルフラグ、MapGroup 状態への依存が残る。「コピーしたから独立したステージになる」とは扱えない。
- 今回の開始イベント抑止は限定的な保護であり、CRO の全コールバックや固有ギミックを作者が掌握できる仕組みではない。

## 次の作業目標: 自作ステージ向けイベント・フラグ制御基盤

作者が次の情報と操作を持てるようにする。

- **イベント一覧**: 発火する場所・タイミング、条件、処理、対象キャラ、読み書きするフラグを表示。表と CRO の両経路を扱い、未解析部分を明示する。
- **フラグ・変数一覧**: 種類、用途名、初期値、保存範囲、読み取り元・書き込み元を表示する。ビット、数値、MapGroup 状態、クリア状態を区別する。
- **イベント作成・編集**: 「条件成立 → 戦闘 → 勝利フラグ → 会話 → 出口開放」を定義できる。一度だけ実行、再入場、初期化、保存再開の規則を指定できる。
- **ステージごとの状態管理**: 元ステージ・別の自作ステージと衝突しない状態領域を設計する。番号が未使用であるとの推測だけでグローバルフラグを割り当てない。再配信・更新に耐える安定したステージ識別と保存形式も検討する。
- **実行確認**: 現在値とイベント履歴を見て、発火・不発の理由を追えるようにする。

### 推奨する順序

1. 開始フック、会話・接触、戦闘後、宝箱、クリアの各発火経路と、状態を読む・書く処理を棚卸しする。
2. 新規自作ステージで元 CRO のどの処理を継承するかを明示する。既存の「イベントなし」複製を出発点として、作者が管理するイベント実行基盤と保存仕様を設計する。元 CRO の完全解析・編集は別の大きな課題として区別する。
3. 最小の完成例として、独自ボスの勝利で専用フラグを立て、会話を一度だけ流し、出口を開くステージを実装する。
4. Azahar で往復・再入場・保存再開を検証する。元 CRO の意図しないイベントが発火せず、別ステージの状態へ影響しないことを合格条件にする。往復階段の到着地点も確認する。

次回は追加の個別クラッシュ対策から始めず、イベントと状態の所有範囲・実行モデル・保存仕様を先に決める。ユーザーは、少なくともイベント一覧・フラグ一覧・フラグを立てる操作の制御がなければ、ステージを作成できる状態とは言えないと明示している。
